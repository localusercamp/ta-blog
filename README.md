# Тестовое задание: Блог

Простой блог на чистом PHP, Smarty и MySQL. PHP-фреймворки не используются.

## Стек

- PHP 8.3
- Smarty 4
- MySQL 8
- Apache
- SCSS
- Docker и Docker Compose

## Возможности

- Главная страница: категории со статьями и 3 последних поста в каждой.
- Страница категории: название, описание, список статей, сортировка по дате или просмотрам, пагинация.
- Страница статьи: изображение, описание, полный текст, категории, дата, просмотры и 3 похожих статьи.
- Связь статей и категорий многие-ко-многим.
- Счётчик просмотров увеличивается при открытии статьи.
- Сидинг категорий и статей, локальные обложки статей.
- Кастомные страницы 404 и 500.
- Адаптивная вёрстка с бургер-меню на мобильных.
- Дополнительные страницы: все разделы и о блоге.

## Маршруты

| Маршрут | Описание |
| --- | --- |
| `/` | Главная страница |
| `/category/{id}` | Категория с сортировкой и пагинацией |
| `/post/{id}` | Статья и похожие материалы |
| `/sections` | Все разделы |
| `/about` | О блоге |

## Структура проекта

```
app/
  Controllers/       Обработка запросов и рендеринг страниц
  Exceptions/        Исключения приложения
  Facades/           Синглтоны DB и View
  Models/            Объекты Category и Post
  Repositories/      SQL-запросы и гидратация моделей
  helpers.php        Хелперы env() и config()
config/config.php    Конфигурация приложения, БД и путей
database/            Схема и сид-данные
docker/              Конфигурация Apache
public/              Корень сайта и собранные ассеты
resources/scss/      Исходники стилей
  abstracts/         Переменные и брейкпоинты
  base/              Сброс стилей, типографика, утилиты
  components/        Стили отдельных компонентов
  pages/             Стили, специфичные для страниц
resources/views/     Smarty-шаблоны
  layouts/           Основной и error-layout
  pages/             Страницы
  partials/          Переиспользуемые фрагменты
  errors/            Шаблоны 404 и 500
storage/smarty/      Скомпилированные шаблоны и кэш Smarty
```

## Как собрать проект

Проект запускается в Docker-контейнерах.

1. Создайте файл окружения:

    ```bash
    cp .env.example .env
    ```

2. Соберите и запустите контейнеры:

    ```bash
    docker compose up -d --build
    ```

3. Откройте приложение: [http://localhost:8080](http://localhost:8080).

По умолчанию приложение доступно на порту `8080`. MySQL при первом старте
автоматически применяет `database/schema.sql` и `database/seed.sql`.

Остановить контейнеры:

```bash
docker compose down
```

Пересобрать образ после изменения `Dockerfile` или зависимостей:

```bash
docker compose up -d --build
```

## Сидинг

Сид-данные лежат в `database/seed.sql`. MySQL применяет их автоматически при
создании тома базы данных.

Чтобы применить сид заново с нуля:

```bash
docker compose down -v
docker compose up -d --build
```

## Стили

Стили написаны на SCSS в `resources/scss/` и собираются в
`public/assets/css/app.css`. Собранный файл хранится в репозитории, поэтому для
запуска через Docker достаточно только Docker.

Пересобрать стили после изменений:

```bash
npm install
npm run build:css
```

Для автоматической пересборки при изменениях:

```bash
npm run watch:css
```

## Принятые решения

Проект сознательно сделан простым и минималистичным. Всё, что не требуется
заданием, не добавлялось, чтобы код оставался понятным и предсказуемым.

- **Без PHP-фреймворка.** Используются только Smarty и собственный слой
  приложения. Роутинг — простой front controller в `public/index.php`.
- **Без ORM.** Вместо ORM — PDO и репозитории с явными SQL-запросами. Так видно,
  какие данные и как выбираются, и нет скрытой магии.
- **Без migration-runner.** Схема и сид заданы SQL-файлами и применяются
  стандартным механизмом MySQL-контейнера. Для локального тестового проекта
  этого достаточно.
- **Без DI-контейнера.** Зависимости передаются через конструкторы вручную:
  контроллеры получают репозитории, репозитории используют единое подключение
  к БД. Фасады `DB` и `View` нужны только как точки доступа к одному инстансу.
- **Без библиотеки роутинга.** Маршрутов немного, поэтому хватает нескольких
  регулярных выражений и статических сравнений.
- **Без CSS-фреймворка.** SCSS разделён по слоям и компонентам, используются
  CSS-переменные и собственные брейкпоинты в стиле Tailwind.
- **Без JS-фреймворка.** JavaScript нужен только для мобильного меню.
- **Без админки и CRUD.** Задание описывает публичную часть блога и сидинг;
  создание, редактирование и удаление статей не требовались.

Такой набор решений позволяет сохранить проект небольшим, но при этом не
смешивать ответственности: контроллеры, репозитории, модели и шаблоны разделены.

## Использование ИИ

Да, при выполнении задания использовалась AI-assisted разработка. ИИ применялся
как помощник на отдельных этапах, а не как генератор проекта целиком: код
писался итеративно, предложения проверялись, правились и принимались вручную.

ИИ использовался для:

- скаффолдинга приложения и базовой структуры директорий;
- Docker-конфигурации и настройки Apache;
- стилей SCSS: структура файлов, компоненты, адаптивность;
- каркасов и заготовок Smarty-шаблонов и переиспользуемых фрагментов;
- сид-данных: текстов статей и локальных SVG-обложек;
- рефакторинга, поиска неиспользуемого кода и проверки ошибок.

Итоговые архитектурные решения, правки и проверка работоспособности выполнялись
вручную.
